# Инструкции для ИИ

## Назначение проекта

Это короткий хаб письменных домашних заданий для **ПМИ, 1 курс, М++, 2026/27**. Пользователь читает его на GitHub. Весь текст для одногруппников находится в `README.md`, условия — в `assignments/`. Этот файл предназначен только для сопровождения проекта.

Сохраняй предпочтения владельца:

- Отдельные разделы по предметам: матанализ, алгебра, комбинаторика, топология.
- Внутри предмета ДЗ идут **по возрастанию номера: 1, 2, 3…**.
- Ссылка из README сразу открывает PDF с ДЗ. В каждом PDF **только домашние задачи**, без семинаров, лекций и вопросов к коллоквиуму.
- Минимум текста: листок, короткая тема или дедлайн, ссылки на сдачу и результаты.
- Не возвращай C++, просмотры лекций, экзамены, карточки предметов, каталоги источников, JSON-дубли и длинные пояснения.
- Не добавляй решения задач. Не меняй учебный год и набор предметов без запроса владельца.

## Откуда брать обновления

Внизу README находятся ссылки на три страницы курсов Wiki. Используй именно их и проверяй соответствие году и потоку. По топологии пока есть только задание с фотографии доски от владельца, без листка и ссылки на курс. Сохраняй эту запись; не придумывай номер ДЗ или условия задач. Владелец уточнил: «до среды» в этом задании означает 23 сентября 2026; не пересчитывай этот срок относительно даты будущего обновления. Когда владелец даст листок, добавь PDF только с нужными домашними задачами. Ссылки на сдачу и результаты в README предоставлены владельцем; сохраняй их, включая нужную вкладку таблицы.

1. Прочитай текущий README и проверь `git status`. Сохрани чужие незакоммиченные изменения.
2. Загрузи страницы всех трёх курсов. Проверь объявления, разделы ДЗ, дедлайны **и ссылки на семинарские листки**.
3. Открой каждый новый или изменённый PDF целиком. Название «семинарский листок» не означает отсутствия домашки: ДЗ может находиться внутри.
4. Проверь также существующие ссылки на PDF: преподаватель может заменить файл по прежнему URL. Сравни содержание, а не только имя и номер.
5. Сопоставь задания и сроки. Учитывай конкретные объявления и уточнения владельца. При противоречии не выбирай дату молча: кратко укажи, что требует уточнения.

Известный случай: на странице матанализа было написано «ДЗ 1 будет задано», хотя **в пяти прикреплённых листках уже были ДЗ 1–5**. Проверяй содержимое файлов; наличие условий само по себе не подтверждает дату назначения или дедлайн.

Если Wiki не открывается, повтори запрос; при необходимости используй браузер **Helium**. Как запасной вариант можно читать публичную Wiki через Jina Reader (`https://r.jina.ai/` + URL). Его кеш может отставать: по возможности сверяй с прямой загрузкой. Не отправляй в такой сервис закрытые таблицы, Classroom и приватные ссылки. Если проверить источник не удалось, сохрани прежние данные и сообщи об ограничении.

## Дедлайны

- Переноси дату и время из источника без догадок. «До начала семинара» не превращай в 23:59.
- Разделяй рекомендуемый и строгий сроки. Сохраняй оговорки о включительности даты, если они есть.
- Не вычисляй «следующий семинар» без подтверждённого расписания. Пиши «Дата не указана» и при необходимости короткое общее правило.
- Не считай дату консультации временем сдачи. Не переносись автоматически на следующий год.
- Не удаляй прошедшие ДЗ: это также архив листков. Не помечай работу как сданную за пользователя.
- Если по матанализу появятся конкретные сроки, добавь колонку «Дедлайн» к существующей таблице, без отдельной страницы.

## Подготовка PDF

Стабильные имена: `analysis-01.pdf`, `algebra-01.pdf`, `combinatorics-01.pdf` и далее. Для подтверждённых отдельных БДЗ или звёздочек используй понятные имена, например `analysis-bdz-01.pdf`.

1. Скачай оригинал во временную папку **вне репозитория**. Не извлекай новую версию из уже обрезанного файла, если нужен оригинал.
2. Найди начало и конец раздела ДЗ. Сохрани все задачи, подпункты, рисунки и звёздочки, относящиеся к этой работе.
3. Если ДЗ занимает отдельную страницу, извлеки её. Если делит страницу с семинаром или вопросами к коллоквиуму, удали постороннее содержимое и обрежь страницу по границам ДЗ. Одного скрытия через CropBox недостаточно, если посторонний текст остаётся извлекаемым.
4. Сохрани исходные формулы и векторный текст; не перепечатывай условия и не заменяй PDF скриншотом. Подойдут PyMuPDF или pypdf; зависимости устанавливай во временное окружение, например через `uv run --with pymupdf`.
5. Отрендери **каждую итоговую страницу** и осмотри её: все задачи на месте, корни, дроби, индексы и скобки не обрезаны, лишних разделов нет. Сравни с оригиналом.
6. Положи только готовый PDF в `assignments/`. В README не должно быть подсказок «ДЗ на второй странице» — файл уже содержит только домашку. Если сама домашка многостраничная, сохрани все её страницы.

## Ссылки и приватность

- **Не публикуй ссылку на таблицу самооценки недельных ДЗ по матанализу.** Владелец явно запретил её добавлять. Можно напоминать проставлять отметки, но без ссылки. Не восстанавливай её из Wiki, старых коммитов или переписки и не копируй даже в этот файл.
- Не путай эту таблицу с итоговыми результатами по матанализу: ссылку на итоговые результаты владелец разрешил, она уже есть в README.
- Сохраняй разрешённые ссылки на формы, Classroom и результаты. Не выгружай оценки, имена студентов или содержимое ведомостей в репозиторий.
- Не отправляй работы, не меняй отметки в таблицах, не вступай в классы и не пиши преподавателям от имени пользователя.
- Репозиторий приватный. Не меняй видимость и доступ. Запрещённая ссылка присутствовала в ранних коммитах: не переписывай историю самостоятельно; перед возможным открытием репозитория сообщи об этом владельцу.

## Завершение обновления

- Обнови README без разрастания текста. Удали устаревшие утверждения, если они опровергнуты новыми данными.
- Общую дату «обновлено» меняй после проверки всех доступных источников по предметам. При частичной проверке сохрани общую дату, при необходимости укажи дату только у изменённого предмета. Не выдавай дату редактирования оформления за дату проверки источников.
- Проверь относительные ссылки, порядок номеров, соответствие номера в таблице заголовку PDF и отсутствие посторонних файлов. Выполни `git diff --check`, просмотри diff и убедись, что запрещённая таблица не добавлена.
- Если ничего не изменилось, не создавай пустой коммит и не пересохраняй одинаковые PDF.
- При запросе обновить этот проект обычные проверенные правки можно коммитить и отправлять в существующий `origin/main`: владелец ожидает обновление GitHub. Если он просит только черновик или локальные изменения, не отправляй их. Добавляй в коммит только относящиеся к задаче файлы; не используй force push.
- Проверь успешное завершение `git push`. В ответе коротко перечисли изменения и дай ссылку на репозиторий. Если данные не удалось проверить или загрузить, скажи об этом прямо.

Эти инструкции описывают работу по запросу. Сами по себе они не запускают обновления по расписанию.
